- Taking a look at changes made since last commit, see if the application docs need to be updated or added to. If so, please do. Follow industry standards (C4 model + Arc42). Note, not all updates will need an update, make a high judgment call - did we change functionality? add new functionality? remove functionality? rename files or variables or endpoints? Basically, did we make a change, such that if someone only read the docs, they will be out of sync on the functionality of the application? If so, update docs, otherwise do not.
- Delete any intermediary files that were created. These are usually text (usually .md) files describing the changes that were made, but can also be testing scripts implementation scripts etc. Any text file describing changes should be deleted with their content incorporated into docs while following the industry standard.

- commit with a descriptive but concise message. Writing a very long message directly on the command line with break the Ptty connection. Message format must follow best practices and conventions. Also, message should be such that if the user reads the git log, just by reading the first sentences of each message, the story of development becomes clear.
